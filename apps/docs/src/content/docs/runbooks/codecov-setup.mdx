## Per-flag uploads

The repo defines two flags in `codecov.yml`:

- `api` — paths under `apps/api/`. Floor: 65% project, 70% patch.
- `ui` — paths under `apps/ui/`. Floor: 70% project, 70% patch.

`apps/docs/` is excluded entirely; the site has no executable code worth
measuring. Templates, build artifacts, migrations, and the generated
openapi schema are also ignored.

## How the upload works

Both workflows produce an lcov report and then call
[`codecov/codecov-action`](https://github.com/codecov/codecov-action):

```yaml
- name: Upload coverage to Codecov
  uses: codecov/codecov-action@e79a6962e0d4c0c17b229090214935d2e33f8354 # v6.0.1
  with:
    files: apps/api/coverage/lcov.info
    flags: api
    name: api-coverage
    fail_ci_if_error: false
    token: ${{ secrets.CODECOV_TOKEN }}
```

The action is SHA-pinned per the workflow lint-meta rule. `flags: api`
or `flags: ui` is the only thing that differs between the two
workflows.

## Enabling on a fork

Codecov is tokenless on public repos. Forks targeting private repos need
a token:

<CommandRun
  title="Wire CODECOV_TOKEN"
  caption="generate a repo upload token from Codecov and stash it as a GitHub secret"
  command={[
    "# 1. Visit https://app.codecov.io/gh/<owner>/<repo>/settings",
    "# 2. Copy the 'Repository Upload Token'.",
    "gh secret set CODECOV_TOKEN --repo <owner>/<repo> --body '<token>'",
  ]}
/>

`fail_ci_if_error: false` keeps the workflow green when the Codecov
service is degraded — coverage tracking is observability, not a merge
gate. The PR-status thresholds in `codecov.yml` are the actual gate.

## Why this and not <X>

We considered the alternatives:

- **Coveralls.** Comparable feature set. Codecov's per-flag handling and
  PR comment ergonomics are stronger for monorepos.
- **Self-hosted coverage report.** Doable but a fresh GitHub Pages site
  per fork is a maintenance burden the template should not impose.
- **No coverage tracking.** What we had until now. Catches regressions
  only when someone runs the gate locally. PR-time visibility is
  better.

## Source

- `codecov.yml` at the repo root — flags, thresholds, ignore patterns.
- `.github/workflows/apps-api-ci.yml` — api upload step.
- `.github/workflows/apps-ui-validate.yml` — ui upload step.
- `apps/api/scripts/quality/check-coverage.ts` — local coverage gate
  the api test suite runs in CI before the Codecov upload.
