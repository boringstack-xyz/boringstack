BoringStack ships slash-command skills in `apps/api/.claude/skills/` and `apps/ui/.claude/skills/`. Each one is a markdown file with frontmatter (`name`, `description`) plus the prompt the agent follows. Type the command in Claude Code, the agent runs the workflow. A fresh fork inherits all of them.

## Full-stack and vertical-slice skills

### `/build-feature`

Builds a feature inside one template. In `apps/api/` that's an endpoint, a CRUD resource, a BullMQ job, an audit-log event, a notification event, or an ACL flag. In `apps/ui/` it's a page, a component, a vertical UI slice, or wiring an existing API endpoint into the SPA.

Triggers: "add a feature", "add an endpoint", "scaffold a resource", "build X", "wire up X", "new route".

### `/add-full-feature`

For resources that need both an API endpoint and a UI page. Runs `/build-feature` on the API, regenerates the OpenAPI client, runs `/build-feature` on the UI against the new endpoint. Use it when the feature crosses the api/ui boundary.

Triggers: "add a full feature", "build X end to end", "new feature, api + ui", "full vertical slice for X", "wire X from db to screen".

## Focused skills

Each of these does one thing. The full-stack skills above delegate to them. You can call them directly when you only want that one thing.

### `/add-audit-event` (api)

Adds a single `auditLogService.record(...)` call to an existing service. Picks an action name from the constants, decides what metadata is safe (no PII), wires it into the right place, writes the sibling test.

### `/add-email-template` (api)

No scaffolder for this one. The skill walks the manual flow: write the Handlebars files, regenerate the precompiled JSON, call `sendTemplate(...)` from the right site, inspect in Mailpit.

### `/add-notification-event` (api)

Wraps `bun run new:notification-event` with the dedup-strategy decision, the render functions, and the dispatcher call. Use it when a new event type belongs in the notifications system.

## Review skills

### `/security-review` (api / ui)

Reviews a branch or PR for security regressions. Runs the Layer 1 CI scanners locally (gitleaks, osv-scanner, bun audit), kicks off Layer 2 agent skills in parallel (differential-review, insecure-defaults, sharp-edges, supply-chain-risk-auditor), then checks BoringStack-specific invariants.

On the API: ACL ability checks on every route, multi-tenant `accountId` scoping, Stripe webhook signature handling, rate limits on credential routes, audit-log coverage on mutations, idempotent BullMQ jobs.

On the UI: no raw `fetch` outside `openapi.ts`, no `dangerouslySetInnerHTML`, no `import.meta.env` outside `src/lib/env/`, no token storage in `localStorage`, no JSX-level user-supplied strings without i18n, CSRF + content-type validation on user-data flows.

Triggers: "security review", "any vulnerabilities in this branch", "audit this PR", "is this safe to merge".
