End-to-end means: a database table, an API route, a typed UI page, tests on both sides, all of it green through `bun run validate`. The agent writes most of the code. You read diffs and check the validate output.

## What you need first

A fresh fork from [boringstack-xyz/boringstack](https://github.com/boringstack-xyz/boringstack) on GitHub (click **Use this template**), Docker (or OrbStack) running, and an agent open in the repo root.

From the cloned repo:

```sh
./setup.sh --up
```

That copies `.env`, generates the GlitchTip secret, and brings the full Compose stack up: Postgres, Valkey, api-dev with migrations applied, ui-dev on `localhost:3001`, OpenAPI client generated. No local Bun or Postgres needed.

Sign in at `http://localhost:3001` as `demo@example.com / password123`.

## 1. Pick something to build

Say you want **support tickets**. Each account lists tickets, creates them, closes them. That's a backend resource (table + service + routes) and a UI page (list + create form).

The skill to use is `/add-full-feature`. It runs the API loop first, regenerates the OpenAPI client, then runs the UI loop against the new endpoint.

## 2. Run the skill

In your agent, type:

```
/add-full-feature

Resource: tickets
Account-scoped: yes
Fields: subject (text, required), body (text, optional), status (open/closed, default open)
UI: list page + create form
```

The agent writes a spec and asks you to confirm. Read it before approving. The spec is cheap to amend; ripping out half-built code is not.

## 3. Approve, then watch the diff

On the API side the agent:

1. Adds the `tickets` table to `apps/api/src/clients/postgres/schema/app.schema.ts` with an `accountId` FK, indexes, and the `@account-scoped accountId` marker that the `drizzle-conventions` ESLint rule reads.
2. Runs `bun run db:generate`. A new `drizzle/000X_*.sql` lands.
3. Writes the five-file resource quintet (`service`, `routes`, `utils`, `constants`, `types`, `schemas`) that `module-boundaries` enforces. Each one gets a sibling test under `tests/api/tickets/`. `lint:meta` fails the PR otherwise.
4. Wires `auditLogService.record(...)` on every mutation. If you asked for one, a notification event too.
5. Runs `bun run validate`. If anything goes red, it loops back and fixes. You don't have to step in unless it gets stuck.

Then it regenerates the OpenAPI types in `apps/ui/` so `apiClient.GET("/api/v1/tickets")` is typed against the new route.

On the UI side, the same kind of pass:

1. New feature folder: `apps/ui/src/features/tickets/{components,Tickets.queries.ts,Tickets.mutations.ts,Tickets.schemas.ts,...}`.
2. TanStack Query against `apiClient`. The lint rule blocks raw `fetch` anywhere outside `openapi.ts`.
3. shadcn components for the list and a create form (React Hook Form + Zod via the regenerated schemas), plus error states.
4. Every JSX string lifts to `apps/ui/src/lib/i18n/locales/en/common.json` and the German parallel. The `no-hardcoded-jsx-strings` rule won't let anything else compile.
5. RTL tests for the page and form.
6. `bun run validate` again.

## 4. See it work

Open `http://localhost:3001/tickets`. The page renders, the create form posts, the list updates. From the terminal:

```sh
curl http://localhost:3000/api/v1/tickets
```

## 5. Ship it

```sh
git checkout -b feat/tickets
git add -A
git commit -m "feat: tickets resource end-to-end"
git push -u origin feat/tickets
gh pr create --fill
```

CI runs the same `bun run validate`. Local green means CI green. Squash-merge.

## Why this fits in 10 minutes

Most of the work isn't writing code, it's holding the project's conventions in your head while you write it. The skill holds them for you: which files to touch, in what order, which sibling tests `lint:meta` will demand, which lint rules block which patterns.

The merge gate is `bun run validate`, the same script in CI. The OpenAPI client is generated from the running API, so a missing field on one side shows up as a type error on the other. Nothing in this loop is hand-wired.

## After the first one

- `/add-audit-event` to instrument something the agent didn't.
- `/add-notification-event` to fire a notification when a ticket closes.
- `/security-review` before opening the PR.
