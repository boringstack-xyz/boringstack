This is the smoke test of the whole template: from a clean clone to a
new account-scoped resource, surfaced in the UI, with audit-log and
notification wiring, and the lint-meta sibling-test bar satisfied.

The agent does most of the typing. You watch the diff and read the
trailing `bun run validate` report.

## Before you start

You should already have:

- A fresh fork from
  [`boringstack-xyz/boringstack`](https://github.com/boringstack-xyz/boringstack)
  via **Use this template** on GitHub.
- Docker (or OrbStack) running.
- The standard one-liner from
  [Quickstart](/quickstart/) completed:
  ```sh
  bun install
  cd infra/compose/compose && ./dev.sh up -d
  cd ../../../apps/api && bun run dev   # tab 1
  cd apps/ui && bun run dev             # tab 2
  ```
- Claude Code (or your agent) open in the repo root.

## Step 1 — Pick the slice

Pretend you're building **support tickets**: each account can list
tickets, create one, and close it. That's an api resource (model +
routes + service) plus a ui page (list + create form).

The right skill is `/add-full-feature` — it drives the api template's
`/build-feature` first, regenerates the openapi-typed client, then
drives the ui template's `/build-feature` against the new endpoint.

## Step 2 — Invoke the skill

In Claude Code, type:

```
/add-full-feature

Resource: tickets
Account-scoped: yes
Fields: subject (text, required), body (text, optional), status (open/closed, default open)
UI: list page + create form
```

The agent now spec'd the resource and confirms what it's about to
build. Read it. If anything's wrong, say so before it starts writing —
the spec is cheap to amend, the implementation is not.

## Step 3 — Approve & watch

Once you approve, the skill runs the canonical loop on the api side:

1. **Schema** — adds the `tickets` table to
   `apps/api/src/clients/postgres/schema/app.schema.ts` (account-scoped
   FK, indexes, the `@account-scoped accountId` comment the
   `drizzle-conventions` rule reads).
2. **Migration** — runs `bun run db:generate` and stages the resulting
   `drizzle/000X_*.sql` file.
3. **Service + routes + utils + constants + types + schemas** — the
   five-file resource quintet enforced by `module-boundaries`. Each
   one ships with a sibling test under `tests/api/tickets/` —
   `lint:meta` will fail the PR otherwise.
4. **Audit + notification wiring** — calls `auditLogService.record(...)`
   at every mutation and (if you asked) wires a notification event.
5. **`bun run validate`** — types, lint, lint:meta, lint:meta docs,
   knip, tests. Anything red goes back into the loop. You don't
   intervene; the agent self-corrects.

Then the openapi schema is regenerated (`bun run generate:api` in
`apps/ui/`) so the typed client has `apiClient.GET("/api/v1/tickets")`
on it.

Then the ui side runs the same loop:

1. **Feature folder** —
   `apps/ui/src/features/tickets/{components,Tickets.queries.ts,Tickets.mutations.ts,Tickets.schemas.ts,...}`.
2. **TanStack Query** wiring against `apiClient`. No raw `fetch`
   anywhere — the lint rule blocks it.
3. **shadcn components** — list page, create form (RHF + Zod via the
   regenerated openapi schemas), error states.
4. **i18n keys** — every JSX string lifted to
   `apps/ui/src/lib/i18n/locales/en/common.json` (and the parallel
   `de/common.json`). The `no-hardcoded-jsx-strings` rule blocks
   anything else.
5. **Tests** — RTL coverage for the page and the form.
6. **`bun run validate`** — same merge bar.

## Step 4 — See it work

```sh
# In the api tab, the new route is live:
curl http://localhost:3000/api/v1/tickets

# In the ui tab, your browser opens /tickets automatically; the page
# renders, the create form posts, the list reflects new rows.
```

## Step 5 — Ship

```sh
git checkout -b feat/tickets
git add -A
git commit -m "feat: tickets resource end-to-end"
git push -u origin feat/tickets
gh pr create --fill
```

CI runs the same `bun run validate` as your local loop. If it passed
locally, it passes on the runner. Squash-merge.

## Why this works in 10 minutes

- **The skill encodes the loop**, not just the prompt. The agent
  knows which files to touch, in what order, and what `lint:meta`
  will reject if it skips a sibling test.
- **The contract is enforced at lint time.** No half-built service
  with a missing test merges. No raw `fetch` slips into the UI. No
  un-translated JSX string makes it past `bun run check`.
- **`bun run validate` is the merge gate.** Same script locally and in
  CI; if green locally, green on the runner.
- **The openapi handshake is generated, not hand-rolled.** The api
  emits the schema, the ui consumes the typed client — adding a field
  on either side reliably lights up the other.
